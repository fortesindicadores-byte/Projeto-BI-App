01 — Visão Geral

O que é o Gestão em Movimento?

Plataforma centralizada de BI da Fortes Indicadores, desenvolvida para substituir o Looker Studio. Cada painel é um arquivo HTML autocontido, publicado via GitHub Pages, sem custo de hospedagem e com total controle sobre layout, dados e lógica de negócio.

Problema resolvido

  • Looker Studio limitado em personalização visual
  • Dificuldade de criar lógicas específicas de negócio
  • Dados dispersos em planilhas sem visualização consolidada
  • Sem controle de acesso unificado

Solução entregue

  • Hub centralizado com autenticação por e-mail
  • Painéis customizados por área (Financeiro, KM, Combustível…)
  • Dados em tempo real do Google Sheets
  • Modo claro/escuro, responsivo, sem instalação

Premissa de design: Zero dependência de servidor próprio, zero custo de infra. Os dados vivem no Google Sheets (onde a equipe já trabalha), a plataforma vive no GitHub Pages (gratuito), e a autenticação usa Supabase (plano gratuito suficiente para a escala atual).

Por que sem framework?

  • Cada painel é um único arquivo .html — sem dependência de build, npm, node_modules
  • Qualquer pessoa com acesso ao repositório pode abrir, editar e entender o código
  • Zero overhead de bundle, carregamento instantâneo
  • Sem breaking changes por atualizações de framework
  • Deploy = commit + push → GitHub Pages publica automaticamente em ~30 segundos

03 — Onde estão os dados

Arquitetura de dados

Os dados residem em planilhas Google Sheets que a equipe já utiliza. Não há extração, transformação ou carregamento (ETL) — os painéis leem diretamente da planilha em tempo real.

Como funciona a leitura

O Google Sheets expõe uma API pública chamada Google Visualization (GVIZ). Cada painel faz uma chamada HTTPS do tipo:

https://docs.google.com/spreadsheets/d/{SHEET_ID}/gviz/tq?tqx=out:json&sheet={ABA}

A resposta é um JSON com todas as linhas e colunas da aba. O JavaScript do painel faz o parse, filtragem e agregação localmente no browser do usuário.

Vantagens da abordagem

  • A equipe atualiza o dado na planilha que já conhece

  • Histórico de dados preservado no Google Drive
  • Sem banco de dados para manter ou migrar

Processamento local: Todo o cálculo de KPIs, deltas, AV%, impacto financeiro, agregações por unidade/projeto e ordenações acontece no JavaScript do browser, do lado do cliente. Não há servidor de processamento.

04 — Segurança

Modelo de segurança

Autenticação — Supabase Auth

  • Login com e-mail + senha (bcrypt)
  • Confirmação de e-mail obrigatória no cadastro
  • Recuperação de senha via link seguro por e-mail
  • Sessões via JWT com refresh automático
  • Logout revoga o token imediatamente

E-mails transacionais — Resend

  • SMTP customizado no Supabase (smtp.resend.com:465)
  • Confirmação de cadastro
  • Link de redefinição de senha
  • Domínio verificado, baixo risco de spam

O que protege o quê

CamadaO que protegeMecanismo
Hub (index.html) Acesso aos painéis listados Supabase Auth — sem token válido, não exibe o grid
Painéis individuais Dados operacionais/financeiros URL direta acessível — dados públicos via GVIZ
Planilhas Google Dados brutos Permissão “qualquer pessoa com o link pode ver” (somente leitura)
Código-fonte Lógica de negócio Repositório privado no GitHub

Limitação conhecida e aceita: Os painéis individuais são acessíveis por URL direta sem autenticação. A proteção atual está no Hub — quem não fizer login não descobre as URLs. Para proteção mais rígida futuramente, pode-se adicionar verificação de sessão Supabase em cada painel individualmente.

Práticas de segurança no código

  • Chave pública (sb_publishable_*) do Supabase — sem segredo exposto no frontend
  • Sem SQL injection possível (sem banco próprio)
  • Sem XSS: dados da planilha são renderizados via textContent
  • HTTPS obrigatório (GitHub Pages força HTTPS)
  • Sem cookies de rastreamento de terceiros

06 — Escalabilidade

Como o sistema escala

Capacidade atual

  • GitHub Pages suporta tráfego ilimitado (CDN global)
  • Supabase Free: 50.000 usuários ativos / mês
  • Google GVIZ: sem limite documentado para leitura
  • Sem banco de dados próprio para sobrecarregar

Adicionar novo painel

  • Copiar visao-financeira/index.html como base
  • Alterar título, SHEET_ID, SHEET_TAB
  • Implementar fetchData() e render()
  • Commit + push → live em 30 segundos
  • Adicionar card no Hub
